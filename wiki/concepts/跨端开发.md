# 跨端开发

## 一句话定义

用一套代码（或一套技术栈）覆盖多个运行端，本质是**在统一开发体验与各端原生能力/性能之间做取舍**；它决定的是"壳"，不改变语言、框架、构建这些下层选择。

## 详细说明

### 端与方案的对应

| 目标端 | 常用方案 | 生态归属 | 主要代价 |
|---|---|---|---|
| 桌面（Windows/macOS） | Electron、Tauri | 前端通用 / Rust | 包体大、内存占用高 |
| 浏览器扩展 | WXT、Plasmo | React 友好 | 各浏览器 API 差异 |
| 移动 App | React Native、Flutter | React 系 / Dart | 原生桥接、性能调优 |
| 小程序 | Taro、uniapp | Taro 跨框架 / uniapp 偏 Vue | 平台限制多、审核约束 |
| 特殊场景 | C++（如 WPS）、Flutter 四端 | — | 门槛高或生态窄 |

### 选型逻辑

1. **先定端，再定栈**：端决定壳，壳反过来约束框架。已经用 React 的项目，桌面走 Electron、扩展走 WXT、移动走 RN 是最省摩擦的路径。
2. **生态一致优先**：Vue 团队做小程序用 uniapp 更顺；React 团队用 Taro 更顺。反着选不是不能跑，是团队要付双重学习成本。
3. **算清隐性成本**：跨端省的是"重复开发"，付出的是"包体、启动性能、原生能力适配、调试链路复杂度"。端越多、原生诉求越强，这笔账越不划算。

### 一个常见误区

把"跨端"当成一门新技术来学。实际上它是最上层封装：底层仍然是 L1 语言、L2 框架、L6 构建那一套。**框架和生态选对了，跨端只是加一个渲染器/容器**。
