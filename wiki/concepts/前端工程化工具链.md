# 前端工程化工具链

## 一句话定义

围绕"代码写出来之后、上线之前"的一整套自动检查与规范工具，核心是三件事分工明确：**查对错（lint）、管排版（format）、验行为（test）**。

## 详细说明

### 三个角色

- **ESLint**：静态分析，找可能的错误和坏味道——未使用变量、`x / 0`、可疑的条件、React Hooks 依赖缺失。它自带少量格式化能力，但那是副业。
- **Prettier**：纯格式化，不管代码对不对，只管缩进、空格、换行、引号。
- **Vitest**：单元测试框架，与 Vite 同一套转换链路，配置和速度都更贴近现代项目。

### 为什么必须分开

lint 和 format 如果都由一个工具包办，规则会互相打架：你在意的"这行太长"和"这里有潜在 bug"是两种完全不同的判断，混在一起会导致要么漏错、要么频繁误报。分开之后规则边界清楚，CI 里也能分别设置"报错即阻断"和"只提示"。

### 新一代工具

Rust 实现的 oxlint / oxfmt 主打速度，适合大仓库和 CI；也出现了把 lint + format 合并到一个二进制的方案（视频里提到一个"检查令"，转写含糊，疑指 Biome），取舍是"配置简单、生态兼容度不如 ESLint"。

### 落地建议

- 新项目：ESLint（规则集用官方推荐 + 框架插件）+ Prettier，提交前跑 lint-staged，CI 强制。
- 大仓库提速：先评估 oxlint 替代 ESLint，oxfmt 替代 Prettier，保留原有规则映射。
- 单测：Vitest 与 Vite 项目天然契合，不必再引入第二套转换链路。
