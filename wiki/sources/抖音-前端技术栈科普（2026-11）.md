# 抖音-前端技术栈科普（2026-11）

## 核心观点

- 这不是教程，而是**一张口语化的前端技术栈全景图**：从"端"开始，依次讲到语言、框架、组件库、代码质量工具、运行时与包管理、构建工具，最后落到跨端封装。作者的组织逻辑是"一个人从零到能干活，会依次碰到什么"。
- 三个最硬的结论：**只想学一门语言就学 JS/TS**；**Node 仍是 80% 份额的运行时地基，精力有限就只学 Node**；**Webpack"必知必会"的说法已经过时，Vite 是当前构建层的主流**。
- 最有价值的不是单个工具的介绍，而是"**生态归属**"这层关系：谁的组件库、谁的框架、谁的构建工具、谁想统一谁。看懂了归属，选型就不会把不同生态的东西硬拼。

## 关键内容摘要

- **端与跨端**：PC / 浏览器 / 移动 / 小程序 / 浏览器扩展各有一套历史语言，跨端需求来自"一套代码、一个岗位覆盖多端"。C++ 可跨两端（WPS），Flutter 可写四端，JS 理论上可写所有端。
- **语言层**：JS 是统称，底下是 HTML、CSS、JS 三件套。TS = JS + 类型，作者称正经项目约 90% 用 TS，并强调"类型对 AI 友好"（类型即上下文，模型能读懂）。
- **框架与组件库**：React 被认为是最成熟方案；Vue 生态并行。组件库分两派——阿里系 Ant Design / Ant Design Pro（中台内部系统，基于 Umi），Google 风格 MUI；Vue 侧用 Element Plus，不要用 Element 2，更不要用教学项目 Element3；公司要自有设计风格用 Headless UI（Tailwind 团队出品，只给无样式组件）。作者反复强调：**问组件库必须问版本**。
- **代码质量**：ESLint 管"潜在问题"（未使用变量、除零），Prettier 管"格式化"（空格、换行）；二者职责不同，ESLint 自带一点格式化能力但不是主业。竞品：oxlint / oxfmt；单测用 Vitest。
- **运行时与包管理**：Node.js 是所有转换步骤（JSX→JS、TS→JS、CSS 处理）的地基，"没有 Node 就没有当前前端生态"；npm 是 Node 的包管理器，也是人指挥工具干活的"沟通层"。Node 仍占约 80%；Bun 主打"更快的 Node"且已被收购；Deno 是 Node 作者的新项目，不兼容生态、用户少、近期才尝试兼容。包管理：Yarn 式微，pnpm 有竞争力，但精力有限就用 npm。
- **构建层**：Webpack 类比 Maven/Gradle，生态最大但慢；Rspack 是它的 Rust 替代，Turbopack 出自 Next.js 团队，Umi 是阿里系构建工具（Ant Design Pro 的底座）。Vite 是当前主流，中小项目几乎全覆盖，大项目也用，并已成为很多框架的"元框架"。
- **Vite 的强与弱**：强在 esbuild 的开发速度 + Rollup 的生产生态、主动放弃 IE；弱在"开发/生产环境偶发不一致"。解法是尤雨溪团队成立 VoidZero，做 Rust 的 OXC 解析器，再基于它做 Rolldown；**Vite 8 起只用 Rolldown**。
- **跨端封装**：React 系桌面用 Electron，浏览器扩展用 WXT 或 Plasmo，移动端用 React Native，小程序用 uniapp（Vue 生态）或作者推荐的 Taro。
