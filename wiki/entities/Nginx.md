# Nginx

## 简介

客户端与具体后端之间的**可控入口层**。外部请求先到 Nginx 的公开地址，再由它按路径或上游分发给内网后端。它不是网站的必需品——单实例、小流量、框架自带 HTTPS 时直连更划算；它是"当横切职责开始重复时才值得引入的一层"。

## 关键事实

- **反向代理**：`location /api/` 配 `proxy_pass http://127.0.0.1:8080`，后端不暴露公网。`location` 与 `proxy_pass` 结尾斜杠是否一致会改变转发路径，是最高频的配置事故。
- **TLS 终止**：证书只配在入口，Nginx 与浏览器完成加密握手，后端走内网 HTTP；证书续期与加密套件收敛到一处，但内网这一段失去加密，跨机房应改为 re-encrypt。
- **静态资源直出**：图片、CSS、JS 由 Nginx 直接返回，可叠加 gzip、`expires`/`Cache-Control`、sendfile，不占应用进程。
- **负载分发**：默认轮询（round-robin）分给多个上游实例；可配 `weight`、`least_conn`、`ip_hash`。加机器时对外地址不变。
- **配置形态**：主配置 `nginx.conf` + `conf.d/*.conf` / `sites-enabled`；改完 `nginx -t` 校验、`nginx -s reload` 平滑生效（不丢连接）。
- **何时不引入**：单实例、访问量小、应用框架已能处理 HTTPS 与静态文件。

> 视频之外，这一层通常还承担：限流与并发连接数、请求体大小与缓冲区、访问/错误日志、WebSocket 与 SSE 升级、健康检查与灰度切流、隐藏后端拓扑。

## 并发模型：为什么一个 worker 能接住一万个连接

- **epoll + 非阻塞**：连接只登记一次，有数据的由内核放进就绪列表；只来半行就先记下、转身处理别的连接，从不干等。一个连接只占一小块内存，**不占一个进程**——容量从"进程数"换成"内存与 fd 数"。
- **master / worker**：master 只读配置、开端口、管 worker；worker 干活。master 先 `listen` 再 `fork`，子进程继承同一个监听套接字；或 `listen 8080 reuseport`，每个 worker 各开一个，由内核分发。
- **一核一 worker**：一个进程同一时刻只能用一个核。
- **reload 不断连接**：新 worker 接班，旧 worker 不再接新连接、处理完手上的请求才退出（优雅退出）。
- **实测量级**（单机单次，不可当基准）：1 万慢连接下，Apache 一万进程约 1.1 GB 且新请求进不来；Nginx 两进程约 112 MB、新请求全进、CPU 约 2%；Caddy 单进程约 212 MB。
