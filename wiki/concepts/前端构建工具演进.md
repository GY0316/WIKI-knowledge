# 前端构建工具演进

## 一句话定义

构建工具负责把"人写的代码"（TS/JSX/CSS Modules/图片）翻译并压缩成"浏览器能高效执行的产物"；它的演进史就是一条**从 JS 实现到 Rust 实现、从双流水线到单流水线**的性能与一致性之争。

## 详细说明

### 三代主线

1. **Webpack（JS 实现，生态最大）**：所有资源都当模块处理，插件/loader 生态极全；代价是冷启动和构建慢。它是"前端的 Maven/Gradle"，但"每个前端必知必会"这句话已经过时——**配置不必手写，产物、分包、缓存、tree-shaking 这些概念仍要懂**。
2. **Vite（双工具）**：开发期用 esbuild 做依赖预构建和转换（快），生产期用 Rollup 打包（产物成熟、插件生态好）。这是"两套流水线"，好处是快且稳，坏处是**开发与生产偶发行为不一致**（转换逻辑、插件系统不是同一套）。
3. **Vite 8 + Rolldown（单工具）**：VoidZero 团队用 Rust 写 OXC（JS 语法解析）→ 基于 OXC 做 Rolldown（打包器）。Vite 8（2026-03）把 Rolldown 作为唯一打包器，统一开发与生产流水线；Rolldown 1.0 在 2026-05 发布，宣称比 Rollup 快 10–30 倍，同时兼容 Rollup/Vite 插件 API。

### 同期其它路线

- **Rspack**（字节）：Webpack 的 Rust 兼容实现，主打"存量 Webpack 项目的低成本替换"。
- **Turbopack**（Vercel / Next.js）：为 Next.js 优化的增量构建。
- **Umi**（阿里）：面向中后台的集成式构建/框架方案，Ant Design Pro 的底座。
- **Vite+**（VoidZero）：想把包管理、lint、format、测试配置统一到一个入口，定位"前端的 Maven/Gradle"。

### 怎么选

- 新项目：直接用 Vite 8，不必再纠结 esbuild/Rollup 组合。
- 存量大型 Webpack 项目：先评估 Rspack 迁移（配置兼容性好），一次迁移拿到大部分提速。
- 中后台一体化：Umi 这类"框架即构建"的方案省心，但会绑定生态，升级受制于框架节奏。
- 判断一个构建工具是否"主流"，看两件事：**是否是框架的默认底座**、**插件生态是否兼容旧协议**。
