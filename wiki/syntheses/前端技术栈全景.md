# 前端技术栈全景

## 一句话结论

把前端当成一条**七层流水线**来理解：端 → 语言 → 框架 → 组件库 → 质量工具 → 运行时/包管理 → 构建 → 跨端封装。选型不是挑"最好的工具"，而是先锁定所属生态（React 系还是 Vue 系），再在同生态内按层补齐——跨生态硬拼组件库和构建工具，是绝大多数踩坑的来源。

## 分层地图

| 层 | 解决什么 | 代表 | 现状（截至 2026-11） |
|---|---|---|---|
| L0 端 | 跑在哪里 | PC / 浏览器 / 移动 / 小程序 / 浏览器扩展 | 端决定上层选择，先定端再定栈 |
| L1 语言 | 写什么 | HTML / CSS / JS，TS | TS 已成事实标准（主流项目普遍覆盖） |
| L2 框架 | 怎么组织页面 | React / Vue / Svelte / Angular | React 最成熟，Vue 生态并行 |
| L3 组件库 | 长什么样 | Ant Design(Pro) / MUI / Element Plus / Headless UI | 绑定框架；**必须问版本** |
| L4 质量工具 | 怎么保证不出错 | ESLint / Prettier / oxlint / oxfmt / Vitest | lint 与 format 职责分离 |
| L5 运行时/包管理 | 工具靠什么跑 | Node.js + npm/pnpm；Bun、Deno | Node 仍是默认地基 |
| L6 构建 | 怎么变成浏览器能跑的 | Vite(8) / Webpack / Rspack / Turbopack / Umi | Vite 主导，Rolldown 已接管 |
| L7 跨端封装 | 一套代码怎么上多端 | Electron / WXT / React Native / Taro / uniapp | 按端选壳，不与 L2 冲突 |

## 各层细节

### L1 语言：JS 是统称，TS 是加了约束的 JS

HTML/CSS/JS 是三个不同职责的"小语言"，不是一门语言的三部分。JS 动态类型，同一个变量可以先后赋字符串和数字；TS 在编译期加类型约束，把这类错误提前暴露。**类型的真正价值不止于防错**：它是给 AI 的上下文——模型看到 `TestCase[]` 就知道结构，不用猜。这也是"TS 对 AI 友好"的实质。

### L2 框架：先选生态，再选框架

React 与 Vue 不是"两个库"，而是两个生态，各自带组件库、路由、SSR 方案、跨端方案。选错生态，后面每一层都得重新选。不想用框架就用原生（vanilla），但工程化收益会明显下降。

### L3 组件库：版本比名字重要

- 阿里系：Ant Design → Ant Design Pro（面向中台/内部系统的完整方案，底座是 Umi）。
- Google 风格：MUI。
- Vue 侧：Element Plus（Vue 3 版本）。Element 2 已过时；社区里还有个 Element3，是自媒体作者做的教学项目，不能上生产。
- 自有设计风格：Headless UI（Tailwind 团队），只提供无样式组件与交互逻辑，样式自己写。

**同一个名字可能是三个不同东西**，问清楚是哪个框架的、哪个大版本，比记名字有用。

### L4 质量工具：查问题 ≠ 管格式

- ESLint：找潜在错误（未使用变量、除零、可疑写法），带一点格式化能力但不是主业。
- Prettier：只负责格式（缩进、空格、换行），不判断对错。
- 新一代：oxlint / oxfmt（Rust 实现，速度优势），单测用 Vitest。

三者的正确分工是"lint 管对错、format 管排版、test 管行为"，混在一起会让规则互相打架。

### L5 运行时与包管理：Node 仍是地基

JSX→JS、TS→JS、CSS 预处理，全都依赖 Node 执行。所以"没有 Node 就没有当前前端生态"不是夸张。npm 是 Node 的包管理器，也是人与工具链之间的"沟通层"。

- **Node**：份额约 80%（作者口头估计），默认选择。
- **Bun**：运行时 + 包管理 + 打包 + 测试四合一，主打速度；2025-12 被 Anthropic 收购，仍保持 MIT 开源。
- **Deno**：Node 作者的新项目，原生 TS、更安全，但早期不兼容 Node 生态导致采用率低；2026-10 团队并入 Cloudflare。
- **包管理器**：Yarn 式微，pnpm 靠硬链接和严格依赖有竞争力，但"精力有限就用 npm"仍成立。

### L6 构建：从"双工具"到"单工具 Rust"

详见 [[前端构建工具演进]]。一句话：Webpack（JS 实现、生态最大、慢）→ Vite（开发用 esbuild、生产用 Rollup）→ Vite 8 + Rolldown（Rust 单一流水线，10–30x 构建提速）。

### L7 跨端：壳在框架之上

详见 [[跨端开发]]。React 系：桌面 Electron、扩展 WXT/Plasmo、移动 React Native。Vue 系：小程序 uniapp。跨生态：小程序 Taro、四端 Flutter。跨端只决定"壳"，不改变 L1–L6 的选择。

## 视频说法与事实核对

| 视频说法 | 核对结果 |
|---|---|
| Vite 8 只用 Rolldown | **属实**。Vite 8（2026-03）以 Rolldown 为唯一打包器，Rolldown 1.0 于 2026-05 发布 |
| Bun 已被收购 | **属实**。2025-12-02 Anthropic 收购 Bun（Oven），保持 MIT 开源 |
| Deno 不兼容生态、近期才尝试兼容 | 大致属实；另有 2026-10 Deno 团队并入 Cloudflare，视频未提 |
| TS 占有率约 90% / Node 约 80% | 作者口头估计，无公开口径；方向成立，数字不可引用 |
| Webpack"必知必会"已过时 | 作为"不必手写配置"成立；但分包、缓存、产物结构这些概念仍要懂 |
| Yarn 江郎才尽 | 是观点不是事实，Yarn 仍在维护，只是新项目多选 npm/pnpm |
| Element3 是教学项目 | 属实，不宜上生产 |
| Vite 未到 90% 是因为 dev/prod 偶发不一致 | 是合理归因之一，但市占还受存量迁移成本、插件兼容影响 |

## 落地建议（三档）

- **入门**：JS → TS → React → 一套组件库 → Vite → npm。构建细节先不深究，先跑通"改代码—热更新—打包上线"。
- **生产项目**：TS + React/Vue + Ant Design 或 Element Plus + ESLint/Prettier（或 oxlint/oxfmt）+ Vite 8 + npm/pnpm，Node 用 LTS。
- **跨端**：先定端，再选壳——桌面 Electron、扩展 WXT、移动 RN、小程序 Taro；Vue 团队做小程序可考虑 uniapp。

## 这一页的边界

视频是"全景速览"，密度高但深度浅。以下主题它只提了一句或完全没讲，真要落地得另找资料：状态管理（Redux/Zustand/Pinia）、样式方案（Tailwind/CSS Modules/CSS-in-JS）、测试体系（单测/组件测试/E2E）、CI/CD 与产物部署、monorepo、微前端、性能与包体优化、可访问性。
